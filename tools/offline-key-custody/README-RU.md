# YAMC — подготовка настоящих публичных идентификаторов

Этот пакет создаёт три **настоящих ключа**, но не подключается к сети, не создаёт
транзакций и не развёртывает программу. Нужен только уже установленный Node.js;
`npm install` не нужен. Используются Ed25519 и генератор случайности Node/OpenSSL.

- `admin.json`: Config admin и начальная upgrade authority. Самый важный ключ;
  обычной ротации Config admin сейчас нет.
- `program.json`: будущий адрес программы; не upgrade authority.
- `mint.json`: будущий адрес токена; не право дополнительной эмиссии.

Все три пока остаются на отдельном компьютере. Publisher, issuer, payer, nonce и
Android signing key этим пакетом не создаются. Старые rehearsal-ключи не использовать.

## Порядок на отдельном Windows-компьютере

1. Распакуйте пакет в отдельную папку, например `C:\YAMC-Key-Custody`.
   В PowerShell перейдите в неё. Проверьте SHA256 `keys.mjs` против значения,
   переданного на рабочем ПК: `Get-FileHash .\keys.mjs -Algorithm SHA256`.
   Хеш рядом с файлом помогает обнаружить повреждение, но не доказывает подлинность
   самого инструмента. Исходник открыт для проверки.
2. Отключите сеть. Выберите локальный каталог вне OneDrive/Dropbox и старых
   тестовых папок. Ограничьте доступ к нему своей Windows-учётной записью;
   Unix mode 0600 не устанавливает Windows ACL. Ключи хранятся обычными JSON,
   **не зашифрованы самим инструментом**. Для носителя/диска используйте своё
   защищённое хранилище; не переносите всю папку на рабочий ПК.
3. Создайте новый набор (папка назначения ещё не должна существовать):

   ```powershell
   node .\keys.mjs generate C:\YAMC-Mainnet-Keys
   ```

   Ожидается `CREATED_AND_CHECKED`. При повторе программа откажется перезаписывать
   папку. При ошибке не удаляйте автоматически частично созданные ключи; сохраните
   папку и сообщите текст ошибки без содержимого JSON.

4. Скопируйте всю `C:\YAMC-Mainnet-Keys` в защищённую резервную копию вне этого
   компьютера. Подключив/разблокировав её на **этом же offline-компьютере**,
   проверьте чтение именно копии (замените `E:` своим путём):

   ```powershell
   node .\keys.mjs verify-backup E:\YAMC-Mainnet-Keys C:\YAMC-Mainnet-Keys\public-identities.json
   ```

   Ожидается `BACKUP_VERIFIED`. Проверяется каждый секрет, соответствие публичному
   адресу и возможность подписи. Это не транзакционная подпись.

5. Перенесите обратно **только `public-identities.json`** в
   `temp\mainnet-identities-return\` на рабочем ПК. Сообщите, прошла ли проверка
   резервной копии. `admin.json`, `program.json`, `mint.json` не присылайте.

В публичном файле находятся адреса и подписи фиксированного сообщения
`YAMC key custody proof v1 / NOT A TRANSACTION`, отдельно для каждой роли.
Это позволяет проверить соответствие ключей адресам без раскрытия секретов.
Подписи не разрешают deployment или перевод средств и не доказывают, что резервная
копия хранится безопасно. Пока не пополняйте адреса SOL.

После возврата файла проверим доказательства, закрепим новые адреса, пересоберём
программу под новый program ID и повторим проверки перед дальнейшим deployment.
